# Voxelheim

A tiny open block world that runs entirely in the browser — explore, dig,
build, and play with friends over room codes. No installs, no server to run.

> Voxelheim is an original game inspired by the voxel-sandbox genre.
> Every texture, sound, and name is generated by code — nothing is copied
> from any commercial game.

## Play with friends

1. One player opens the site and clicks **Create a new world** — you get a
   5-letter room code (shown top-right, and in the pause menu).
2. Everyone else opens the same site, types the code, clicks **Join**.
3. That's it. Connections are peer-to-peer (WebRTC via PeerJS's free public
   broker), so there is no game server — the host's browser is the world
   authority.

Notes:

- The host's tab must stay open; if the host leaves, the room ends.
  The host's world (seed + every edit) is saved in their browser every few
  seconds, so hosting the same code again resumes the world — the menu's
  "saved worlds" list makes this one click.
- Room codes are checked to be unique while creating; if the broker is
  unreachable, check your internet connection.
- Desktop Chrome / Edge / Firefox are best. Very strict corporate NATs can
  occasionally block direct WebRTC connections.

## Run it locally

Any static file server works:

```bash
cd voxelheim
python3 -m http.server 8123
# open http://localhost:8123
```

No build step, no dependencies to install — three.js and PeerJS load from
CDN, everything else is plain ES modules.

## Deploy to GitHub Pages

1. Push this folder to a GitHub repository.
2. Repo **Settings → Pages → Source: `main` branch, `/ (root)` → Save**.
3. Your game is live at `https://<username>.github.io/<repo>/`.

With the GitHub CLI:

```bash
git init && git add -A && git commit -m "Voxelheim"
gh repo create voxelheim --public --source=. --push
gh api repos/<username>/voxelheim/pages -X POST -f source='{"branch":"main","path":"/"}' --input - <<< '{"branch":"main","path":"/"}'
```

## Custom domain

1. In the repo, add a file named `CNAME` (no extension) containing exactly
   your domain, e.g. `play.example.com`. Commit and push.
   (Or set it in Settings → Pages → Custom domain, which creates the file.)
2. At your DNS provider, point the domain at GitHub Pages:
   - Apex domain (`example.com`) — A records:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - Subdomain (`play.example.com`) — CNAME:
     `<username>.github.io.`
3. Back in Settings → Pages, confirm the domain, then enable
   **Enforce HTTPS** (required for the best experience and may take a few
   minutes to issue the certificate).

## Tech notes

- ~1,900 lines of dependency-free ES modules + three.js (pinned CDN) +
  PeerJS. Static hosting only.
- World: seeded simplex noise → biomes (plains, forest, desert, snowy),
  caves, ore veins, trees, water. Chunks are 16×16×80, meshed with
  per-face culling and vertex ambient occlusion, streamed in/out around
  the player on a per-frame time budget.
- Deterministic generation means joiners only receive the seed plus the
  edit log — joins are fast even in heavily-built worlds.
- Day/night cycle (10 min), drifting clouds, stars, sun & moon; the sky
  brightness drives all world materials.
- All 55 block textures are drawn to a canvas atlas at startup; all sound
  effects are WebAudio synthesis. Zero binary assets.


## Known limitations

Creative-mode scope: no survival, crafting, mobs, or redstone. Water is
static (no flow simulation). If the host closes their tab the room ends
(world is saved). Audio autoplay policies require one click before sounds
start — click the world once.
